# 작업 규칙 (모든 세션이 먼저 읽는다)

설명 문서: https://claude.ai/artifact/EEEYrfETXXSEteRuBgbG1K
성공 기준: 오래 도는 것이 아니라, Jake가 지정한 범위에서 검증된 진전을 만들고 정해진 시점에 멈추는 것.

## 읽는 순서
1. 이 파일 → `STATUS.md` → `INBOX.md`. 그 밖의 문서는 해당 작업에 필요할 때만.
2. 코드 위치는 `../STRUCTURE.md`에서 찾고 관련 구역만 연다.
3. 게임 방향은 리부트 기획서(https://claude.ai/artifact/WQJGbUtoUTxygjKwSBudk5)의 관련 절만.

## 한 번의 실행
- Jake가 지정한 작은 작업 **1개**만 한다. INBOX에 승인된 항목이 없으면 새 일을 만들지 않고 끝낸다.
- 시작 전에 `tasks/<ID>.md`를 `_TEMPLATE.md`로 만들고 계약(범위, 완료 조건, 검사)을 채운다. 요청에서 추론되는 것은 직접 채우고, 게임 방향이 바뀌는 불확실성만 묻는다.
- `node loop/guard.js start <ID>` → 구현 → 검사 → `guard.js attempt pass|fail --sig <실패 한 줄> --improved yes|no`.
- 가드가 CONTINUE가 아니면 그 자리에서 멈춘다. 긴 단계 앞에서는 `guard.js check`.
- 끝나면 `tasks/<ID>.md`에 결과 보고, `STATUS.md` 갱신, INBOX 항목에 상태 표시.

## 한도 (`limits.json`)
- 수정: 최초 구현 뒤 최대 2회(후보 3개). 시간: 20분. 같은 실패 2회 또는 2회 연속 개선 없음이면 중단.
- 작업이 크면 한도를 늘리지 말고 쪼갠다.
- 자동 시작, 주기 실행, 실패 후 재시작은 하지 않는다. 예약 작업을 만들지 않는다.
- 사용량 제한이나 인증 오류를 만나면 재시도하지 않고 `guard.js halt usage_limit`.

## 검사 고르기 (`tests/run.sh p0|p1|full`)
| 바꾼 것 | 검사 |
|---|---|
| 화면만: render, title, sprites, fx, pixfont, i18n | p0 + 바뀐 장면 스크린샷 확인 |
| 소리: audio | p0. 소리는 들을 수 없으므로 "미확인"으로 보고 |
| 규칙과 저장: board, rules, run, config, meta, achievements | p1 |
| 밸런스 수치, 스폰, 난이도 | full (balance 포함, 느림) |
| zip 만들기, 제출 준비 | full + zip 다시 만들기 |
| 영향 범위를 모르겠음 | p1 (좁게 추측하지 않는다) |
- 기계가 판정할 수 있는 것은 스크립트로. 같은 판정을 눈으로 다시 하지 않는다.
- 수정이 없고 같은 조건에서 통과한 검사는 반복하지 않는다.
- 전체 로그는 `tests/logs/`에 두고 요약과 실패 부분만 읽는다.
- 화면이 바뀌면 실제 렌더를 본다. 작은 수정은 모아서 한 번에 찍는다.
- 봇은 플레이어 입력만 쓴다. 내부 값을 바꿔 통과시키지 않는다.

## 통과와 승인은 다르다
- 검사 통과 ≠ 재미, 손맛, 미술 승인. 이 셋은 Jake만 승인한다.
- 보지 못한 화면, 듣지 못한 소리, 실제 휴대폰 동작은 "미확인"으로 적는다.
- 검사는 통과했지만 Jake 확인이 남으면 상태는 "완료(승인 대기)".

## 독립 검토와 아트 (필요할 때만)
- 일반 코드 작업은 검토자를 부르지 않는다.
- 아트 변경이나 Jake가 중요하다고 표시한 작업에서만 새 검토자 1명, 1회. 두 번째 검토자는 판단이 크게 갈릴 때만.
- 검토자에게는 결과 화면, 요구, 참고 화면(`reference/`), 평가표만 준다. 만든 쪽의 자기평가와 이전 점수는 주지 않는다.
- 아트는 먼저 수치 기준(해상도, 픽셀 배율, 팔레트, 실루엣 가독성)을 통과시킨 뒤 검토로 넘긴다.
- 후보는 모두 보존하고 최고 후보를 `champion/`에 둔다. 새 후보는 최고 후보와 나란히 놓고 비교한다.
- 구체적 결함 없이 점수만 올리는 수정은 하지 않는다. 기준이 Jake 취향과 다르면 더 돌리지 말고 기준 조정을 요청한다.
- 검토자를 부른 횟수를 결과 보고에 적는다.

## 보존
- Jake가 직접 바꾼 것과 기존 결정은 건드리지 않는다.
- 미완료 작업은 보존하되 완료로 표시하지 않는다.
- GamePix 제출, 공개, 유료 구매는 Jake가 직접 지시할 때만.
- INBOX의 끝난 항목은 지우지 않고 [완료]를 붙인다. STATUS에 다음 작업이 없으면 "없음 — 대기".

## 검토자 평가표 (아트 디렉터)
당신은 픽셀 아트 게임의 아트 디렉터다. 만든 사람도 의도도 모른다. 첨부한 화면과 요구, 참고 화면만 보고 답하라. 칭찬은 쓰지 않는다.
- 점수(1~5): 픽셀 배율과 글꼴의 통일 / 캐릭터가 살아 보이는가 / 색과 대비 / 썸네일 크기에서 눈에 띄는가 / 요구를 충족했는가
- 가장 큰 문제 세 가지: 어느 화면의 무엇인지, 왜 문제인지 한 문장씩.
- 화면에서 확인할 수 없는 것은 "확인 불가".

## 검토자 평가표 (처음 온 플레이어, 첫인상 작업에만)
당신은 게임 포털에서 썸네일을 눌러 처음 들어온 플레이어다. 첨부한 화면만 보고 답하라. 칭찬은 쓰지 않는다.
- 점수(1~5): 무엇을 하는 게임인지 아는가 / 다음에 무엇을 눌러야 할지 아는가 / 한 판 더 할 이유가 보이는가
- 가장 큰 문제 세 가지. 확인할 수 없는 것은 "확인 불가".
